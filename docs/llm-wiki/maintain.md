# Wiki 维护协议（Agent 必读）

本文件规定 Agent 如何管理 `docs/llm-wiki/`。  
**没按本文件回写，任务不算完成。**

---

## 1. 记忆分层

| 层 | 文件 | 规则 |
|----|------|------|
| 入口 | 仓库根 `AGENTS.md` | 硬性规则，短；细节链到本目录 |
| 路由 | [README.md](./README.md) | 只放目录与原则 |
| 真相 | [status.md](./status.md) | 当前做到哪；每次操作更新 |
| 审计 | [log.md](./log.md) | 只追加；禁止改写、禁止删除旧条 |
| 专题 | 其余 `*.md` | 该领域的可执行契约 |
| 证据 | [assets/](./assets/) | 效果图、截图；改视觉时同步 |

禁止把「下一步计划」只写在聊天里。要执行的下一步写进 `status.md`。

---

## 2. 开工

```text
读 AGENTS.md
  → 读 llm-wiki/README.md
  → 读 status.md
  → 按任务读 1–3 个专题页
  → 动手
```

可跳过专题预读的，仅限：用户明确说「只改 Wiki 某页」、或纯确认「status 里已写明的下一步」且该页已读过。

不要默认通读产品仓全部 `docs/llm-wiki/`。官网需要的契约已经吸收进本目录；上游变更时按 [sources.md](./sources.md) 对一次再改本页。

---

## 3. 什么叫「一次操作」

下列任一发生，就必须回写：

- 新增 / 修改 / 删除源码、样式、文案、图片、字体
- 新增 / 升级 / 删除依赖或构建脚本
- 部署、绑域名、改 DNS、改 Pages 项目、改短链
- 验权、轮换 token 策略（只记结论，不记密钥）
- 下载 URL、按钮映射、`downloads.json` 接入方式变化
- 设计决策、主题策略、截图资产替换
- 发现并确认的事实（例如某 tag 仍无稳定别名）
- 范围变更（做 / 不做皮肤 Apply 等）

只聊天、未改仓库且未改变已记录事实 → 可以不回写。

---

## 4. 回写步骤（收工）

按顺序：

1. **专题页**改成现在时。删掉已经过时的「尚未 / 计划」句；实现后把祈使句改成陈述句。
2. **status.md**：更新状态表、阻塞、下一步。日期用当天（会话里的 Today）。
3. **log.md 追加一条**，模板如下。
4. 若新增或删除了专题文件：改 README 目录表。
5. 若换了效果图：替换 `assets/` 并在 design / theme 里改文件名说明。

### log 条目模板

```markdown
## YYYY-MM-DD · 一句话标题

- **操作者**：agent / 人名
- **触发**：用户原话压缩，或「按 status 下一步」
- **改动**：文件或系统上实际发生了什么
- **Wiki**：同步了哪些页
- **结果**：做成了什么；若失败写失败原因
- **未做 / 下一步**：只写立刻可执行的一条
```

禁止在 log 里贴 token、cookie、完整 Authorization 头。

---

## 5. 完成判定

Agent 可以宣称「做完了」仅当：

- [ ] 代码或配置的变更已落盘（若本轮有实现）
- [ ] 相关专题页与 `status.md` 一致
- [ ] `log.md` 已有本轮条目
- [ ] 回复里没有依赖「请记住」才能让下一任 Agent 接着干

---

## 6. 冲突时听谁的

| 冲突 | 听谁 |
|------|------|
| 本 Wiki 与聊天旧结论 | Wiki |
| 本 Wiki downloads 与产品仓 `website-downloads.md` | **产品仓**为发版权威；本页是官网消费侧。产品仓改了契约，先改本 `downloads.md` 再改站点 |
| 效果图与已实现页面 | 效果图是视觉目标；实现后以代码为准，并回写 design/theme 注明偏差 |
| status 与专题页 | 以能核对的事实为准（仓库文件、线上 HTTP、CF API），立刻改掉错的一侧 |

---

## 7. 禁止

- 把 token / 账号密码写入 Wiki
- 用「见聊天记录」代替 status
- 在用户可见页面里写 Wiki 术语、Agent 指令、TODO
- 复制产品仓整份 llm-wiki
- 为了回写而写空话（「做了一些优化」）——必须点名路径或 URL
